# AGENTS.md

Guide for AI coding agents working in this repository. Humans: see README.md and CONTRIBUTING.md.

## What this is

PlayGoblin is a QA bot that plays a game and reports bugs. An engine side (Unity package, Unreal plugin, or anything that writes the run-folder format in `docs/PROTOCOL.md`) walks the game and writes `events.jsonl`. A Python CLI turns run folders into findings, a report and GitHub issues. An MCP server exposes the CLI to agents.

## Map

| Path | What |
|---|---|
| `cli/playgoblin/` | Python package (no hard dependencies). `checks/` = one pure function per check `(run, config) -> findings`; `dedupe.py`, `evidence.py`, `report.py`, `pipeline.py`, `service.py`, `issues.py`, `llm.py`, `mcp_server.py`, `writer.py` |
| `cli/tests/` | pytest; `conftest.py` has `make_run` to build fake run folders |
| `unity/` | Unity package `com.playgoblin.unity` (Runtime, Editor, Tests). Namespaces/classes start with `PlayGoblin` |
| `unreal/PlayGoblin/` | Unreal plugin (C++, experimental, not yet compiled) |
| `samples/sandbox` | Unity project that hosts the package tests |
| `samples/broken-game` | Unity level with planted bugs + clean twin. Scenes are generated by `Assets/Editor/BrokenGameBuilder.cs`; never hand-edit the `.unity` files |
| `samples/unreal-sandbox` | Unreal sample project (experimental) |
| `scripts/verify_samples.py`, `verify_unreal.py` | Walk the samples with a real engine and compare reports with planted bugs |
| `skills/playgoblin/SKILL.md`, `.claude-plugin/`, `.mcp.json` | Claude Code skill / plugin |

## Run the tests

```bash
cd cli && pip install -e ".[dev]" && python -m pytest -q        # Python, no engine needed
```

Unity (use the installed editor path; edit mode is quick, play mode takes minutes):

```bash
Unity -batchmode -nographics -projectPath samples/sandbox -runTests -testPlatform EditMode -testResults out/em.xml -logFile out/em.log
Unity -batchmode -nographics -projectPath samples/sandbox -runTests -testPlatform PlayMode -testResults out/pm.xml -logFile out/pm.log
python scripts/verify_samples.py --unity <Unity.exe> --seeds 1 2 3     # opens a window: frames need rendering
```

Unreal: needs Unreal Editor closed (Live Coding blocks the build) and a short project path (Windows 260-character limit). See `unreal/README.md`.

## Conventions and rules

- Checks are deterministic code. Do not put an LLM in a check. `llm.py` only writes an optional summary.
- Never report something without evidence (an event, frame or log line). A stuck spot seen once is "unconfirmed", not dropped and not asserted.
- `file-issues` and `playgoblin_file_issues` are dry runs unless explicitly confirmed. Keep it that way.
- Game text (error messages, button labels) goes into HTML reports: always escape it (`report.py` does).
- Event `data` values are strings. Positions are metres, Y up (`docs/PROTOCOL.md`).
- Keep the CLI free of hard dependencies; numpy/Pillow are optional extras and checks must skip cleanly without them.
- Windows consoles: stdout is reconfigured to UTF-8 in `cli._safe_console`; do not print raw emoji elsewhere.
- Unity: never hand-edit `.unity`, `.prefab`, `.asset` or move `.meta` files separately. Avoid APIs deprecated in Unity 6000.4 (see `UiText` wrappers in `MenuCrawler.cs`); the build must stay at zero warnings.
- Write tests with the real format an engine emits. A past bug: Unity writes error kind `exception` (lowercase) while fixtures used `Exception`, so real exceptions were ranked wrong for a while.
